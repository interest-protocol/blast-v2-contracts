## TL;DR

All six earlier findings are correctly remediated in this snapshot. After a full pass over `sui/dex`, `sui/auto_lp`, and the SDK dex/auto-lp adapters plus shared codec, I found **no remaining high- or medium-severity defect**. ## Remediation verification (one line each)

- **DEX F1 (zero-claim events):** `pool.move:316-322` emits `FeesClaimed` only when `quote > 0`; `migration.move:116-119` returns before accrual on empty collections. The silent on-chain settle this creates is replay-safe: settlement is linear in fee growth, so a reducer keeping the stale checkpoint computes the identical cumulative entitlement at the next emitted event. Resolved.
- **DEX F2 (overflow diagnostic):** `pool.move:65-66,170` uses dedicated `EVersionOverflow` (code 17); pinned by `activation_overflow_has_a_distinct_diagnostic`. Resolved.
- **DEX F3 (fee consumes target):** `launch.move:98-101` rejects `apply_up(target) >= target` (`ENoMigrationQuotePrincipal`, code 82) before ticket destruction; since the curve closes at exactly the target, migration principal is now provably ≥ 1. Resolved. I also checked the native seed floor: with the fixed 10^18 Meme supply and ≥1 bps provision, `initial_shares ≥ sqrt(10^14) > 1000`, so `ESeedTooSmall` cannot strand a native migration.
- **AutoLP F1 (pump-direction consumption):** `auto_lp/vault.move:249-254` checks `meme_used/quote_used` from the actual `deposit_amounts` preview against the signed maxima before withdrawal; nothing mutates the pool between that preview and `add_liquidity`, so the amounts are identical. Pinned by the price-pump and independent-maximum tests. Resolved.
- **AutoLP F2/F3:** external-collection test via `funded_for_testing` asserts source ID, split amounts, and event bytes; exact-deadline, revoked-admin, and empty/dust paths are covered. Resolved.

## Findings

**L1 (Low, SDK design gap) — event decoder binds one execution package, breaking cross-upgrade replay.** `sdk/src/lib/package-events.ts:99-101` rejects any event whose `packageId` differs from the single configured execution ID, while the reducers (`dex/reducer.ts:46-47`) require complete ordered history. After a future upgrade, pre-upgrade events (old emitter ID, same original type address) would be rejected unless the caller decodes history in per-generation segments. Not exploitable and not reachable pre-publication, but it contradicts the replay-completeness promise across the upgrade lifecycle ADR 0076 anticipates. Minimal fix: accept an allow-set of emitter package IDs (or rely on the original-type-address check alone, which is the authoritative identity). Missing regression: decoding an event emitted under a second lineage package ID.

**L2 (Low, SDK consistency) — `tx.coin` type not normalized in two builders.** `DexTransactions.buy/sell` normalize the coin type before `tx.coin` (`transactions.ts:337,356`), but `create` (`:381-386`) and `addLiquidity` (`:405-410`) pass the raw caller string. If the coin-selection intent matches by exact type string, a short-form input could fail selection only on those two paths. Minimal fix: apply `normalizeStructTag` in both, matching buy/sell. Missing regression: builder test with a short-form (`0x2::sui::SUI`-style) type through `create`/`addLiquidity`.

## Test gaps (not bugs)

- **Move `blast_fun_dex` unpinned aborts:** no test asserts `EIdenticalAssets` (code 1), `ESeedTooSmall` (3), the sell/dust `EZeroAmount` boundaries (8), `remove_liquidity` `EMinimumOutput`, `EInsufficientShares` (13), `EPositionNotEmpty` (14), `EAccountingOverflow` (15), or `EClockReversed` (16). The testing standard requires each declared abort pinned with exact code and location.
- **SDK reducer branch coverage:** `applyDexEvent` is only exercised for `PoolCreated`/`Swapped` (plus dedupe). The verification logic in `LiquidityChanged` (settle-then-resize), `FeesClaimed` (recomputed-equality), `PositionClosed`, `MaximumFeeChanged`, `VersionActivated`, and all four `migration.*` branches has no TypeScript test, including their mismatch/throw paths.
- **SDK reads:** `getNativeLpPosition` (migration `PositionKey` lookup) has no mocked-client test, unlike the auto-lp children and canonical-pool lookup; `previewDexSell` on a burn pool is untested (buy-side burn is covered).
- **Vector provenance:** `sdk/test/fixtures/dex-fees.json` is a copy of `docs/vectors/dex-fees.json`; ensure both are regenerated from `generate_dex_fees.py` in one step so the SDK copy cannot drift or be hand-edited.
